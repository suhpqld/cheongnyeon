# 05 추가 서류 (사진 찍기, AI 읽기, 추가로 챙길 서류)

> **AI에게:** `docs/00_공통_먼저읽기.md`를 먼저 끝까지 읽는다. AI 호출은 01의 `callAI({ kind: 'vision' | 'text' })`, 상한은 `useAiCall`, 인증은 `requireApp`, 날짜는 `lib/format.ts`(`todayKST`, `formatDateKo`, `ddayFrom`, `ddayLabel`)를 쓴다. 고치지 않는다.

## 이 기능이 하는 일
주민센터에서 "서류를 더 내라"는 종이(보완 요청서)를 받았을 때:
1. 사진을 찍거나 글로 적으면 AI가 **무엇이 빠졌고, 어디서 받고, 언제까지인지** 읽는다.
2. 화면 이름은 **"추가로 챙길 서류"**. **제출 날짜와 남은 날**을 가장 크게 보여 주고, 쉬운 풀이 옆에 **종이에 적힌 원문**을 같이 보여 준다. (피드백 기획 5, 디자인)
3. 기한은 사용자가 **원문과 비교해서 확인**해야 확정된다.
4. 빠진 서류는 04의 준비 카드 목록에 자동으로 붙는다. 이미 있던 서류면 새로 붙이지 않고 "추가 요청에도 있어요"로 표시한다.
5. 표, 도장, 손글씨가 섞인 **시연용 예시 종이 3종**을 만들고 사진 모델을 미리 시험해서 기록한다. (피드백 개발)

## API

### 🔒 `POST /api/supplement/parse`
- 요청 `{ appId, imageDataUrl?: string, text?: string, today: 'YYYY-MM-DD' }` (둘 중 하나만)
- `requireApp` → `useAiCall`
- `imageDataUrl`이면 `callAI({ kind: 'vision', system, user, imageDataUrl, timeoutMs: 45000 })`, `text`면 `kind: 'text'`
- 라우트 파일에 `export const maxDuration = 60`
- 응답을 zod로 검사 (`SupplementParsed`). 그다음 **코드가 검사** (AI가 읽고, 코드가 계산한다):
  - `deadline`이 진짜 날짜인지 (`2026-02-30` 같은 것 거르기). 아니면 null
  - `items`가 0개면 422 `{ error: 'unreadable', message: '글씨를 잘 못 읽었어요.' }`
  - `placeGroup`이 6개 값이 아니면 `onsite`
- 실패하고 `DEMO_MODE === 'true'`면 `lib/demo/sample-notice.ts`의 예시 결과(기한은 today + 7)
- 응답 `SupplementParsed` (**아직 저장하지 않는다**. 저장은 다음 API)

### 시스템 프롬프트 `lib/ai/supplement-prompt.ts`
```
너는 복지 신청을 돕는 도우미 "복냥이"의 서류 읽기 담당이다.
주민센터나 구청이 보낸 보완 요청서(추가 서류를 내라는 안내문)를 읽고, 어르신도 이해할 수 있게 정리해 JSON으로만 답한다.
종이에는 표, 도장, 손글씨가 섞여 있을 수 있다. 읽을 수 없는 부분은 지어내지 않는다.

규칙
1. items: 더 내야 하는 서류를 하나씩.
   - name: 종이에 적힌 서류 이름 그대로
   - originalText: 그 서류가 적힌 줄을 종이에 적힌 글자 그대로 (예: "1. 임대차계약서 사본 1부 (확정일자 날인본)")
   - easyName: 쉬운 이름 (10자 안팎, 예: "집 계약서 복사본")
   - easyExplain: 무엇인지 쉬운 존댓말 한두 문장
   - issuePlace: 어디서 받거나 떼는지 쉬운 말. 모르면 "주민센터에 물어보세요"
   - placeGroup: home(집에 있는 것), onsite(주민센터에서 받아 쓰는 것), bank(은행), work(회사나 일하는 곳), tax(세무서, 홈택스), gov24(주민센터나 정부24에서 떼는 증명서) 중 하나
2. deadline: 제출 기한을 YYYY-MM-DD로. 연도가 없으면 today의 연도로 하되, 그 날짜가 today보다 두 달 넘게 이전이면 다음 해로. 기한이 없거나 읽을 수 없으면 null.
3. deadlineOriginalText: 기한이 적힌 부분을 종이 글자 그대로 (예: "제출기한: 2026년 11월 28일까지"). 없으면 null.
4. officeName, officeContact: 종이에 적힌 대로. 없으면 null. 지어내지 않는다.
5. hardWords: 종이에 나온 어려운 행정 용어와 쉬운 풀이 (최대 5개). 예: {"word":"각하","easy":"신청이 받아들여지지 않고 끝나요"}
6. consequenceEasy: 기한을 넘기면 어떻게 되는지 종이에 적혀 있으면 쉬운 말로, 없으면 null.
7. summaryEasy: 무엇을, 언제까지, 어디에 내면 되는지 쉬운 존댓말 한두 문장.
8. 글자를 읽을 수 없거나 보완 요청서가 아니면 items를 빈 배열로 한다.
9. 이름, 주민등록번호, 계좌번호, 주소는 출력하지 않는다 (originalText에 있으면 그 부분만 ○○로 바꾼다). 수급 가능 여부를 판단하지 않는다.
10. 출력은 아래 JSON 하나뿐이다.
{"programName":null|"...","items":[{"name":"...","originalText":"...","easyName":"...","easyExplain":"...","issuePlace":"...","placeGroup":"..."}],"deadline":null|"YYYY-MM-DD","deadlineOriginalText":null|"...","officeName":null|"...","officeContact":null|"...","hardWords":[{"word":"...","easy":"..."}],"consequenceEasy":null|"...","summaryEasy":"..."}
```
- user 메시지: `today: {today}` + (글 모드면) 적은 글

### 🔒 `POST /api/apps/[id]/supplements`
- 요청 `{ parsed: SupplementParsed, sourceText?: string }`
- `supplement_request` 저장: `parsed_json`, `deadline`, `deadline_confirmed: false`, `office_contact`, `source_text` (사진은 저장하지 않는다)
- `mergeSupplement` (아래)로 체크리스트 갱신
- 상태를 `supplementing`으로 (`ALLOWED_STATUS_CHANGES` 확인, 이미 supplementing이면 그대로)
- 응답 `{ supplementId, addedCount, matchedCount }`

### 🔒 `GET /api/apps/[id]/supplements/[sid]`
- `{ supplement: Supplement, items: ChecklistItem[] }` (items = `supplement_id`가 sid인 항목)

### 🔒 `PATCH /api/apps/[id]/supplements/[sid]`
- `{ deadline?: 'YYYY-MM-DD', deadlineConfirmed?: true, submitted?: true }`
- deadline이 오면 저장하고, `supplement_id = sid`인 체크리스트 항목의 `due_date`도 같이 바꾼다
- `submitted: true` → `submitted_at = now()`, 신청 건 상태 `submitted` (`submitted_at`도 갱신)
- 응답 `{ supplement }`

## 규칙 `lib/rules/supplement.ts`
- `normalizeDocName(name)`: 괄호와 괄호 안 글 지우기 → "최근 n개월(간, 분)", "본인 명의", "사본", "원본", "1부", "각1부" 지우기 → 띄어쓰기 지우기
  - "임대차계약서 사본 1부 (확정일자 날인본)" → "임대차계약서"
  - "급여명세서 (최근 3개월)" → "급여명세서"
- `mergeSupplement(existing: ChecklistItem[], items: SupplementItem[], deadline, sid)`:
  1. 정규화한 이름이 기존 항목(기본이든 추가든)과 **똑같으면**: 새로 넣지 않고 그 항목에 `due_date = deadline`, `also_requested = true`, `is_done = false`(다시 달라고 했으니), `supplement_id = sid`
  2. 똑같은 게 없으면 새 항목: `source: 'supplement'`, `supplement_id: sid`, `doc_name: name`, `easy_explain: easyName + '. ' + easyExplain`, `issue_place`, `place_group`, `due_date: deadline`
  3. 포함 관계로 합치지 않는다 ("부양의무자 금융정보 등 제공 동의서"와 "금융정보 등 제공 동의서"는 다른 서류)

## S9 받은 종이를 보여 주세요 `/a/[id]/photo`
- 지금 할 일: "받은 종이를 사진으로 찍어 주세요"
- 읽어 줄 말: "주민센터에서 받은 종이를 사진으로 찍어 주세요. 밝은 곳에서, 종이 전체가 나오게 찍어요."
- 화면: 복냥이(md) + 말풍선 "받은 종이를 보여 주세요. 제가 쉽게 풀어 드릴게요." + 촬영 안내 그림(네모 틀 안에 종이 SVG) + 세 줄 "☀ 밝은 곳에서", "📄 종이 전체가 나오게", "✋ 흔들리지 않게"

| 버튼 | 누르면 |
|---|---|
| `📷 사진 찍기` (primary) | `<input type="file" accept="image/*" capture="environment">` |
| `🖼 앨범에서 고르기` | `<input type="file" accept="image/*">` |
| `✏️ 글로 적기` | 큰 입력창 "종이에 적힌 서류 이름과 날짜를 그대로 적어 주세요." + `확인` → 글 모드로 parse |
| `예시 종이로 해보기` (작게) | `SAMPLE_NOTICE_TEXT(today)`를 글 모드로 parse (시연 안전장치) |
| `← 뒤로` | `/a/[id]` |

사진을 고른 뒤:
- 미리보기 (크게) + `이 사진으로 할게요` (primary) / `다시 찍기`
- `이 사진으로 할게요`:
  1. `lib/client/image.ts`로 줄이기: 긴 변 1600px, JPEG 0.8 (Vercel 요청 4.5MB 제한)
  2. `POST /api/supplement/parse` → 로딩 `Loading` "복냥이가 종이를 읽는 중이에요"
  3. 성공 → `POST /api/apps/[id]/supplements` → 줄인 사진을 **sessionStorage** `boknyang.photo.{sid}`에 (탭을 닫으면 사라짐. 서버에는 안 보냄) → `/a/[id]/extra/{sid}`
  4. 실패(422, 타임아웃) → "글씨를 잘 못 읽었어요. 조금 더 가까이, 밝은 곳에서 다시 찍어 주세요." + `다시 찍기` / `✏️ 글로 적기` / `예시 종이로 해보기`

## S10 추가로 챙길 서류 `/a/[id]/extra/[sid]`

### 화면 (위에서 아래로)
1. AppShell: 지금 할 일 = 기한 확인 전이면 "종이에 적힌 날짜와 같은지 확인해 주세요", 확인 후면 "추가로 챙길 서류를 {11월 28일}까지 내 주세요". back `/a/[id]`
2. **기한 상자** (가장 크게, 티켓 모양: 굵은 점선 테두리)
   - **기한 확인 전** (`deadlineConfirmed: false`) → `DeadlineConfirm`:
     - "종이에 적힌 날짜와 같은지 확인해 주세요"
     - 원문 상자: 📄 "종이에 적힌 말" + “{deadlineOriginalText}” (테두리 있는 인용 상자, 진한 글씨)
     - 복냥이가 읽은 날짜: **{11월 28일 (토)}** (40px)
     - `✅ 맞아요` (primary) → `PATCH { deadlineConfirmed: true }`
     - `📅 날짜 고치기` → 큰 년, 월, 일 선택 3개 + `이 날짜로 할게요` → `PATCH { deadline, deadlineConfirmed: true }`
     - 기한이 null이면: "기한이 안 보여요. 종이를 보고 날짜를 넣어 주세요." + 날짜 선택 + `기한이 없어요` (주민센터에 물어보라는 안내 + 전화 버튼)
   - **기한 확인 후** → 아주 큰 두 줄: **"11월 28일 (토)까지"** / **"7일 남았어요"** (`ddayLabel`)
     - 오늘이면 "오늘까지예요", 지났으면 "기한이 3일 지났어요. 바로 주민센터에 전화해 보세요." (warn 색 + 글)
3. **추가로 챙길 서류 {n}개** — 서류마다 `ExtraItem` 카드:
   - **easyName** (22px 굵게) / easyExplain / "📍 {issuePlace}"
   - 📄 "종이에 적힌 말" 인용 상자: “{originalText}”
   - 기존 목록에 있던 서류면 "이미 준비 카드에 있던 서류예요. 다시 챙겨 주세요."
4. **어디에 내나요**: officeName + `📞 전화하기` (`tel:{officeContact}`, 있을 때만)
5. **쉽게 말하면**: summaryEasy
6. **어려운 말 풀이** (hardWords 있으면): "각하 → 신청이 받아들여지지 않고 끝나요"
7. **기한을 넘기면** (consequenceEasy 있으면)
8. `📷 원래 사진 보기` (sessionStorage에 있을 때만) → 사진 크게
9. 주의 글: "사진에서 읽은 내용이라 틀릴 수 있어요. 받은 종이와 꼭 같이 확인하세요."
10. Disclaimer
- 읽어 줄 말: summaryEasy + " 기한은 {11월 28일}, {7일 남았어요}."

## S14 시연용 예시 종이 `/demo/notice` (피드백 개발: 표, 도장, 손글씨)
노트북에 띄우거나 인쇄해서 폰으로 찍어 보는 **가짜 종이**. AppShell 없이 A4 비율 흰 종이 모양.
- 모든 판: 종이 위에 크게 비스듬한 워터마크 **"시연용 예시"**, 기관명과 사람 이름은 "○○", 전화는 `02-0000-0000`. 실제 기관 로고, 실제 직인 모양을 쓰지 않는다.
- 기한은 **오늘 + 7일**로 매번 계산 (v3만 오늘 + 5일)

| 판 | 주소 | 모양 | 시험하는 것 |
|---|---|---|---|
| v1 기본 | `/demo/notice` 또는 `?v=1` | 공문 문단 + 번호 목록 | 기본 읽기 |
| v2 표와 도장 | `?v=2` | 서류 목록이 표(번호, 서류명, 비고), 오른쪽 아래 빨간 동그라미 도장(가운데 글자 "예시") | 표 읽기, 도장 겹침 |
| v3 손글씨 | `?v=3` | v1에 기한만 손글씨 느낌 글꼴(`next/font/google`의 Nanum Pen Script)로 "11/26까지!!", 밑줄 낙서 | 연도 없는 손글씨 날짜 |

### v1 글 (`lib/demo/sample-notice.ts`의 `SAMPLE_NOTICE_TEXT(today)`, `예시 종이로 해보기`와 DEMO_MODE에도 씀)
```
[시연용 예시]
사회보장급여 신청 관련 보완 서류 제출 요청

수신: ○○○ 귀하

귀하께서 신청하신 서울형 기초보장제도 관련 소득 재산 조사를 위하여
```

## 모델 시험 (P0, 01 전에 시작, 피드백 개발)
1. 예시 종이 3판을 노트북 화면에 띄우고 시연 폰으로 찍는다. 판마다 **반듯하게, 비스듬히, 어둡게** 3장 = 9장
2. OpenRouter 사진 모델 후보 2~3개 (예: 기본값 `google/gemini-2.5-flash`와, 목록에서 이미지 입력이 되는 다른 모델 1~2개)로 같은 프롬프트 시험
3. `notes/05_모델_시험.md`에 표로 기록:

| 모델 | 사진 | 서류 3개 다 맞음 | 기한 맞음 | 원문 맞음 | 걸린 시간 |
|---|---|---|---|---|---|

4. 가장 잘 맞고 10초 안쪽인 모델을 고르고, PM에게 `OPENROUTER_VISION_MODEL` 값을 알려 Vercel에 넣게 한다.
5. 발표에 쓸 한 줄을 적는다: "표, 도장, 손글씨 샘플 9장 중 n장에서 서류와 기한을 정확히 읽었고, 틀릴 때를 대비해 원문을 같이 보여 주고 날짜는 사용자가 확인한다."
