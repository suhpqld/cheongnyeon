# 10 새 기획: 주민센터 한 번에 끝내는 신청 준비

> **AI에게:** 이 문서가 복냥이의 **새 기준 기획**이다. 00~08 문서와 다르면 **이 문서가 우선**이다. 단, 00의 공통 약속(파일 주인 규칙은 13장으로 대체, 보안 구조, git 규칙, 디자인 색과 캐릭터, 말투)은 그대로 따른다.

---

## 1. 한 문장

> **복냥이는 복지를 신청하려는 사람이, 신청서 양식을 미리 채우고 필요한 서류를 빠짐없이 준비해서, 주민센터에 한 번만 가서 신청을 끝내게 돕는 앱이다.**

## 2. 왜 필요한가

- 신청서는 주민센터에 가서야 처음 본다. 칸마다 무엇을 적어야 하는지, 어떤 서류가 필요한지는 **쓰다 보면 그때 알게 된다.**
- 그래서 "서류가 없어서 다시 오세요"가 생기고, 주민센터를 두세 번 오간다.
- 일용직처럼 하루를 빼면 일당을 잃는 사람, 평일 낮에 시간을 내기 어려운 사람, 가족이 따라가야 하는 어르신에게는 **한 번 더 가는 것 자체가 큰 비용**이다. 결국 신청을 포기한다.
- 기존 서비스(복지로, 서울복지포털, 안내 챗봇)는 "무엇을 받을 수 있는지"는 알려 주지만, **신청서를 채우고 서류를 준비하는 일은 혼자 해야 한다.** (현직자 피드백도 이 빈틈을 정확히 짚었다고 평가)
- 120 다산콜에 확인한 결과, **집에서 미리 채운 사회보장급여 신청서를 가져가도 접수된다.** 그래서 "집에서 다 준비해 가는" 방식이 실제로 통한다.

## 3. 핵심 메커니즘 (바꾸지 않는다)

```
① 신청할 복지 고르기 ("서울형 기초보장을 신청하고 싶어요")
        ↓
② 그 복지의 신청서 양식 불러오기 (사회보장급여 신청서 + 소득 재산 신고서)
        ↓
③ 양식에 필요한 내용 채우기
   - 쉬운 질문에 답하며 채우거나 (말, 버튼)
   - 양식 화면에서 칸을 눌러 직접 타이핑
        ↓  (채우는 동안)
④ "이 답 때문에 이 서류가 필요해요", "이건 확인이 필요해요"를 그때그때 깨닫는다
        ↓
⑤ 준비물 확인: 서류, 확인할 정보, 자주 빠지는 것까지 "남은 것 0개"가 될 때까지
        ↓
⑥ 출력: 미리 채운 신청서 양식 + 준비 카드(챙길 서류, 받는 곳, 할 말) → 프린트 또는 PDF
        ↓
⑦ 완벽히 준비된 상태로 주민센터 한 번 방문 → 접수
        ↓ (그래도 서류를 더 내라고 하면)
⑧ 받은 종이를 사진으로 찍으면 추가 서류를 정리해서 ⑤로 되돌린다 (안전망)
```

**결과:** 헛걸음과 "무엇을 어디서 떼야 하는지 몰라 헤매는 일"이 줄어든다. 시간 내기 어려운 사람이 하루 안에 신청을 끝낸다.

## 4. 원칙 (피드백 반영, 그대로 유지)

1. **수급 여부를 판정하지 않는다.** "받을 수 있어요", "대상이에요" 금지. 결과 화면마다 "받을 수 있는지는 구청에서 조사해서 정해요."
2. **틀린 값이 양식에 그대로 들어가지 않게.** 모르는 값은 칸을 비우고 "확인 후 적기", 대충 말한 금액도 칸을 비우고 옆에 "말씀하신 금액: 약 30만 원, 통장에서 확인 후 적기".
3. **AI가 읽고, 코드가 계산한다.** AI는 말과 사진을 값으로 바꾸고, 필요한 서류, 남은 것 개수, 기한은 코드가 규칙으로 계산.
4. **개인정보 최소.** 이름, 주민등록번호, 전화번호는 **출력 화면에서만 타이핑하고 저장하지 않는다.** 추가 서류 사진도 저장하지 않는다.
5. **함께 쓰는 사람을 전제로.** 본인, 가족, 주민센터나 배움터 도우미 모두 쓸 수 있다 (피드백 2).
6. **"두 번 갈 일이 없다"고 단정하지 않는다.** 화면과 발표에서는 "한 번에 낼 수 있게 준비해요", "헛걸음을 줄여요"라고 말한다.

## 5. 사용자

| 누구 | 상황 | 복냥이가 주는 것 |
|---|---|---|
| **정민호 (31세, 관악구, 일용직, 1인가구)** | 하루 빠지면 일당이 없다. 평일 낮 주민센터를 여러 번 못 간다 | 밤에 집에서 양식을 다 채우고 서류 목록을 받아, 하루 만에 끝낸다 |
| **이순례 (76세, 노원구) + 아들 김민수** | 어르신 혼자 웹과 서류는 어렵다. 아들이 주말에 같이 한다 | 아들이 옆에서 질문을 읽어 주고 같이 채워서, 평일에 한 번만 모시고 간다 |
| 주민센터, 배움터 도우미 | 창구에서 반복 설명이 많다 | 미리 정리된 양식과 서류를 받는다 |

## 6. 화면과 기능

라우트는 새로 정한다. 기존 화면 파일은 13장 표대로 재사용하거나 교체한다.

### S1 신청할 복지 고르기 `/`
- 지금 할 일: "신청하고 싶은 복지를 골라 주세요"
- 맨 위: 복냥이(hero) + **"주민센터, 한 번에 끝내요"** + 설명 "신청서를 미리 채우고 필요한 서류를 빠짐없이 챙겨 드려요. 준비가 끝나면 출력해서 주민센터에 한 번만 가면 돼요."
- **복지 목록 카드**
  | 복지 | 상태 | 누르면 |
  |---|---|---|
  | 서울형 기초보장제도 | **신청 준비 가능** (남색 카드) | S2 |
  | 국민기초생활보장 (생계, 의료, 주거급여) | 준비 중 (회색) | 확인 창 |
  | 기초연금 | 준비 중 | 확인 창 |
  | 장애인연금 | 준비 중 | 확인 창 |
  | 서울형 긴급복지 | 준비 중 | 확인 창 |
  - 준비 중 확인 창: "{이름}은 아직 준비 중이에요. 지금은 서울형 기초보장제도만 준비해 드릴 수 있어요. 같은 신청서를 쓰는 제도부터 차례로 추가할 예정이에요." [서울형 기초보장 준비하기] [닫기]
  - 목록은 DB `welfare_program`에서 읽는다. `status` 칸(available, soon)을 추가한다. 색만으로 구분하지 않고 "신청 준비 가능", "준비 중" 글자를 쓴다.
- 아래 작은 버튼: `🔢 준비하던 것 이어서 하기` (8자리 번호), `📮 주민센터에서 서류를 더 내래요` (S8로)
- 맨 아래: 소리, 글씨 설정, "이름과 주민등록번호는 저장하지 않아요."

### S2 신청서 양식 불러오기 `/p/[programCode]`
- 지금 할 일: "어떤 신청서를 쓰는지 확인해 주세요"
- **불러온 양식**을 보여 준다:
  - 📄 사회보장급여 신청서 (공식 양식 1쪽 미리보기 그림)
  - 📄 소득 재산 신고서
  - "적을 칸 15개, 함께 낼 서류는 답에 따라 정해져요"
- **누가 쓰고 있나요?** 본인 / 가족이 도와줘요 / 주민센터나 배움터 도우미 (가족, 도우미면 질문이 "신청하시는 분은..."으로)
- **채우는 방법 고르기** (둘 다 같은 답 저장, 중간에 바꿀 수 있음)
  - `💬 질문에 답하며 채우기` (추천, 말이나 버튼) → S3 질문 모드
  - `⌨️ 양식에 직접 적기` (가족, 도우미용) → S3 양식 모드
- 시작을 누르면 신청 건 생성 → **이어서 하기 번호 8자리 안내** → S3

### S3 신청서 채우기 `/a/[id]/fill`
두 모드가 **같은 답(answer 테이블)**을 쓴다. 위에 모드 전환 탭.

**공통 위쪽 줄 (항상 보임)**
- "신청서 15칸 중 7칸 채웠어요" 진행 막대
- "📋 챙길 서류 4개, ⚠ 확인할 것 1개" (누르면 지금까지의 목록을 펼쳐 봄)

**질문 모드**
- 기존 질문 엔진 그대로: 한 화면 한 질문, 말로 답하기(듣고 있어요, 크게 확인, 다시 말하기, 버튼으로 고치기), 되묻기, 잘 모르겠어요(어디서 확인하는지 안내), 대충은 알아요
- 질문 위에 작은 글: "신청서의 **{공식 칸 이름}** 칸이에요" (양식과 연결된 느낌)

**양식 모드**
- 공식 양식 1쪽 그림 위에 칸마다 입력칸을 겹쳐 보여 준다 (13장의 양식 데이터)
- 칸을 누르면: 큰 입력창 + 그 칸의 쉬운 질문과 도움말 + 🎤 말하기
- 질문 모드에서 답한 값은 이미 채워져 보인다
- 이름, 주민등록번호, 전화번호 칸은 회색 "출력할 때 적어요"(저장 안 함)

**④ 깨닫는 순간 (두 모드 공통, 이 앱의 핵심 장면)**
답을 저장할 때마다 코드가 계산:
- 그 답 때문에 **새로 필요해진 서류**가 있으면 → 카드: 복냥이(card) + "📋 이 답 때문에 챙길 서류가 생겼어요" + 서류 이름, 쉬운 설명, 어디서 받는지 + `지금 갖고 있어요` / `챙겨야 해요` (체크리스트에 바로 반영) + 읽어 주기
- **잘 모르겠어요, 대충 금액**이면 → "⚠ 확인할 것이 생겼어요: {칸}. {어디서 확인하는지}"
- 그 답과 관련된 **자주 빠지는 것**(precheck)이 있으면 → "💡 주민센터에서 자주 다시 달라는 거예요: {질문}" + 예, 아니요
- 다 채우면 → S4

### S4 준비물 확인 `/a/[id]/ready`
- 지금 할 일: "남은 것을 0개로 만들어 주세요"
- 맨 위 아주 크게: **"주민센터에 한 번에 내기까지 남은 것 3개"** (0개면 복냥이 happy + "준비 끝! 이대로 가면 한 번에 낼 수 있어요")
- 남은 것 = 안 챙긴 서류 + 확인할 것 + 아니요, 모름으로 답한 자주 빠지는 것
- 세 칸 탭 (피드백 디자인): `📋 챙길 서류` (안 챙긴 것 먼저, 체크) / `📍 받으러 갈 곳` (은행, 주민센터, 정부24 등 묶음, 지도, 120) / `🗣 주민센터에서 할 말` (AI 문장, 읽어 주기)
- 확인할 것은 줄마다 `어디서 확인해요?` + `값 넣기` (S3로)
- 버튼: `🖨 출력하러 가기` (S5), `👨‍👩‍👧 가족에게 보내기` (보기 전용 링크, 7일, 금액 숨김)

### S5 출력 `/a/[id]/print`
- **1장: 미리 채운 공식 신청서 양식** (사회보장급여 신청서 1쪽 그림 + 채운 값)
  - 출력 직전에 이 화면에서만: 이름, 주민등록번호, 전화번호 타이핑 (저장 안 함)
  - 모르는 값, 대충 금액은 빈칸 + 작은 "확인 후 적기" 표시
  - 서명 칸은 비움 ("주민센터에서 직접 서명해요")
- **2장: 준비 카드** (한 장) 챙길 서류 체크 목록(받는 곳 묶음), 양식에 안 들어간 나머지 칸(옮겨 쓰기용), 주민센터에서 할 말, 낼 곳
- 맨 위 안내: "집에서 미리 채운 신청서를 가져가도 접수돼요 (120 다산콜 확인). 서류와 함께 주민센터에 내세요."
- `🖨 출력하기` (window.print, PDF로 저장 가능)
- 아래: `🏢 주민센터에 다녀왔어요` (S6)

### S6 다녀왔어요 `/a/[id]/visit`
- `✅ 접수됐어요` → S7 / `📮 서류를 더 내래요` → S8 / `아직 안 갔어요` → S4

### S7 접수 완료 `/a/[id]/done`
- 복냥이(happy) + "한 번에 끝냈다냥! 수고 많으셨어요." + 다음 안내(구청 조사 후 글로 알려 줌, 보통 한 달)
- **"준비 완료"(S4)와 "접수 완료"(S7)를 단계 표시에서 따로 보여 준다** (피드백 디자인)

### S8 추가 서류 (안전망) `/a/[id]/extra`
- 받은 종이 사진 찍기, 글로 적기, 예시로 해보기 → AI가 읽기
- **원문을 옆에** 보여 주고, **기한은 사용자가 원문과 비교해 확인** (피드백 5)
- 빠진 서류를 S4 목록에 추가 → "다시 남은 것 2개" → 준비되면 다시 방문
- 원문의 이름, 휴대전화, 주민번호는 코드로 가린다

### 이어서 하기 `/resume`, 가족 보기 `/s/[code]`
- 기존 그대로 (8자리, 5번 틀리면 잠금 / 보기 전용, 7일, 금액 숨김)
- 이어서 하기는 **남은 것부터** 보여 준다 (피드백 디자인): 채우는 중이면 S3, 아니면 S4

```sql
  field_key text,                     -- form_field.key (null이면 저장하지 않는 칸)
  local_only text check (local_only in ('name','rrn','phone','signature')), -- 출력 화면에서만 타이핑
  page int not null default 1,
  x numeric not null, y numeric not null, w numeric not null, h numeric not null, -- 그림 대비 퍼센트
  render text not null default 'text' check (render in ('text','check')),        -- 글자 또는 체크 표시
  check_value text,                   -- render가 check면 이 값일 때 ✓
  font_pt numeric not null default 10
);
alter table form_template enable row level security;
alter table form_slot enable row level security;
```
- 양식 그림(`public/forms/ssa_p1.png`)과 `form_slot` 위치값은 공식 양식 PDF로 만든다 (PM이 PDF를 받아 오면 칸 위치를 잡아 seed로 넣는다).
- 질문 모드의 칸(`form_field`)과 양식 칸(`form_slot.field_key`)이 같은 key로 연결된다. 그래서 어느 모드에서 채워도 같은 값이다.

## 8. 계산 규칙 (코드)

- **새로 필요해진 서류:** 답 저장 전후로 `document_rule`을 `matches()`로 평가해서, 전에는 false 후에는 true인 규칙
- **남은 것 개수:** 안 챙긴 `checklist_item` + 보이는 답 중 unknown 또는 isApproximate + 해당되는 precheck 중 결과가 no, unknown, 없음
- **진행:** 보이는 필수 칸 중 답한 수 / 전체
- **양식 칸 값:** `displayForForm(field, answer)` 모름과 대충 금액은 빈 문자열 + 표시 / choice는 공식 양식의 체크 위치로 / 금액은 숫자에 쉼표
- 기존 `lib/rules/condition.ts`, `lib/format.ts`를 재사용

## 11. 시연 시나리오

1. **문제 (30초):** "일용직 민호 씨는 주민센터에 갔다가 서류가 없어서 돌아왔어요. 다시 가려면 또 일당을 포기해야 해요."
2. S1 서울형 기초보장 고르기 → S2 양식 불러오기 (공식 신청서 그림) → 가족 모드
3. S3 질문 모드: "보증금 오백에 월세 이십오만 원" → **"이 답 때문에 임대차계약서가 필요해요"** 카드 (핵심 장면)
4. 연금 "한 삼십만 원쯤" → 확인할 것 생김 / 저축 잘 모르겠어요 → 확인 방법
5. 양식 모드로 바꿔 보기: 공식 양식 위에 값이 채워져 있음
6. S4 "남은 것 3개" → 체크하며 0개 → "준비 끝!"
7. S5 출력: 미리 채운 공식 신청서 + 준비 카드 (120 확인 문구)
8. S6 접수됐어요 → S7 "한 번에 끝냈다냥!"
9. (시간 남으면) 서류를 더 내래요 → 사진 → 다시 남은 것 2개
10. **마무리:** "준비 완료와 접수 완료까지 주민센터는 한 번. 같은 신청서를 쓰는 기초연금, 장애인연금으로 데이터만 넣으면 넓어져요."
