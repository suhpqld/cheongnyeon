# 04 내기 전 점검, 제출 준비 카드, 옮겨 쓰는 카드

> **AI에게:** `docs/00_공통_먼저읽기.md`를 먼저 끝까지 읽는다. 조건 계산은 01의 `lib/rules/condition.ts`(`matches`, `visibleFields`), 표시는 `lib/format.ts`(`displayAnswer`, `formatDateKo`, `ddayLabel`), 받는 곳 이름은 `lib/constants.ts`의 `PLACE_LABEL`을 쓴다. 고치지 않는다.

## 이 기능이 하는 일
1. **내기 전 점검** `/a/[id]/precheck`: 자주 나오는 보완 사유를 질문 하나씩 미리 점검한다. (피드백 기획 4)
2. **제출 준비 카드** `/a/[id]/card`: **챙길 서류 / 받으러 갈 곳 / 주민센터에서 할 말** 세 칸으로 나눠 보여 주고, 안 챙긴 서류가 먼저 보인다. (피드백 디자인)
3. **옮겨 쓰는 카드** `/a/[id]/print`: 공식 신청서 칸 이름과 순서대로 정리한 **출력용 한 장**. 주민센터가 미리 채운 종이를 받아 주든 아니든, 보면서 옮겨 쓰면 된다. (피드백 기획 1, 개발 pdf-lib)

## API

### 🔒 `GET /api/apps/[id]/card`
1. `requireApp`
2. program, fields, answers 읽기 (answers는 field key로 묶음)
3. **기본 서류 목록 다시 만들기** (`lib/rules/checklist.ts`의 `rebuildBaseChecklist`, 매번 해도 가벼움):
   - `document_rule`을 sortOrder 순으로, `matches(rule.condition, 보이는 답만)`이 참인 것
   - 지금 DB의 `source: 'base'` 항목과 비교: 새로 맞는 것은 추가, 더는 안 맞는 것은 삭제, 이름이 같으면 그대로 둠 (`is_done` 유지)
   - `source: 'supplement'` 항목은 건드리지 않는다
4. 응답 `CardData`:
```ts
interface CardData {
  app: Application;
  programName: string;
  place: { district: string | null; dong: string | null };   // 답에서
  checklist: ChecklistItem[];          // 정렬: 안 챙긴 것 먼저 → 추가 요청 기한 가까운 것 먼저 → sortOrder
  docsReady: boolean;                  // 1개 이상이고 모두 isDone
  checkTasks: { key: string; label: string; display: string; checkGuide: string | null }[];  // 보이는 답 중 'unknown' 또는 isApproximate
  precheckPending: { id: string; checkQuestion: string; fixEasy: string; result: PrecheckResult | null }[]; // 결과가 no, unknown, 또는 아직 안 함
  scriptInput: CardScriptRequest;      // 03에 보낼 재료 (answerLines는 displayAnswer로 만든 "칸 이름: 값" 목록 중 사는 곳, 가구, 집 섹션)
  activeSupplement: { id: string; deadline: string | null; deadlineConfirmed: boolean } | null; // 아직 안 낸 가장 최근 추가 요청
}
```

### 🔒 `PATCH /api/apps/[id]/checklist/[itemId]`
- `{ isDone: boolean }` → 그 신청 건의 항목인지 확인 후 저장 → `{ item }`

### 🔒 `GET /api/apps/[id]/precheck`
- 해당되는 점검 (`matches(rule.condition, 보이는 답)`)과 지금까지의 결과 → `{ rules: PrecheckRule[], results: Record<ruleId, PrecheckResult> }`

### 🔒 `PUT /api/apps/[id]/precheck`
- `{ ruleId, result: 'yes' | 'no' | 'unknown' }` → upsert → `{ ok: true }`

## S5 내기 전 점검 `/a/[id]/precheck` (피드백 기획 4)
02의 확인 화면에서 `맞아요, 다음으로`를 누르면 온다.

### 들어올 때
- `GET precheck`. 해당되는 점검이 0개면 바로 `/a/[id]/card`로.
- 아직 안 한 첫 점검부터 하나씩 (한 화면에 하나).

### 화면
- 지금 할 일: "주민센터에서 자주 다시 달라고 하는 것을 미리 확인해요"
- 첫 점검 위에만 안내: "주민센터에서 서류를 다시 달라고 하는 경우가 많아요. 미리 확인하면 한 번에 끝낼 수 있어요."
- 진행: "점검 2 / 5"
- 복냥이(sm) + **점검 질문** (`checkQuestion`, 28px 굵게)
- 작은 상자 "왜 확인하나요?": `whyEasy`
- 관련 서류가 있으면: "관련 서류: {relatedDoc}"
- 읽어 줄 말: 점검 질문 + whyEasy

| 버튼 | 누르면 |
|---|---|
| `✅ 예, 됐어요` | result yes → 다음 점검 |
| `아니요` | result no → **고치는 방법** 상자를 보여 줌 (`fixEasy`, 큰 글씨, 읽어 주기) + `알겠어요, 다음` → 다음 점검 |
| `잘 모르겠어요` | result unknown → 고치는 방법 상자 → `알겠어요, 다음` |
| `나중에 할게요` (작게) | 나머지를 건너뛰고 카드로 (안 한 것은 카드와 현황의 남은 일에 남음) |
| `← 뒤로` | 이전 점검, 첫 점검이면 `/a/[id]/review` |
- 마지막 점검이 끝나면 → `/a/[id]/card`
- 점검 결과는 판정이 아니다. "이러면 탈락이에요" 같은 말을 절대 쓰지 않는다.

## S6 제출 준비 카드 `/a/[id]/card`

### 화면 구성 (위에서 아래로)
1. AppShell: 지금 할 일은 상황에 따라
   | 상황 | 지금 할 일 |
   |---|---|
   | 추가 서류 요청이 있음 | "추가로 챙길 서류를 {11월 28일}까지 내야 해요" |
   | 안 챙긴 서류가 있음 | "챙길 서류 {n}개를 준비해 주세요" |
   | 서류 준비 완료 | "서류를 다 챙겼어요. 주민센터에 내러 가요" |
   back: `/a/[id]` (현황)
2. `<StageTracker compact ... />` (06)
3. 제목 "제출 준비 카드" + 작은 글 "{구} {동} 주민센터에 낼 것" (동 모름 → "사는 동 주민센터에 낼 것")
4. (추가 요청이 있으면) 빨간 테두리 띠: "📮 추가로 챙길 서류가 있어요. {11월 28일 (토)}까지, {7일 남았어요}" → 누르면 `/a/[id]/extra/{sid}`
5. **세 칸 탭** (큰 버튼 3개를 나란히, 고른 탭은 굵은 테두리 + 밑줄, 글자로도 "선택됨")
   - `📋 챙길 서류` + 남은 개수 ("3개 남음")
   - `📍 받으러 갈 곳`
   - `🗣 주민센터에서 할 말`
   - 처음 열면: 안 챙긴 서류가 있으면 1번 탭, 다 챙겼으면 3번 탭
6. 탭 내용 (아래)
7. 아래 고정 줄: `🖨 옮겨 쓰는 카드 출력`, `<ShareButton appId />`
8. 큰 버튼 `🏢 주민센터에 다녀왔어요` → `/a/[id]/visit`
9. 작은 글 "주민센터에서 서류를 더 달라고 할 수도 있어요." + Disclaimer

### 탭 1: 📋 챙길 서류
- 위: 진행 "10개 중 3개 챙겼어요" + 막대
- 다 챙기면: 복냥이 happy + 큰 초록 상자 "**서류 준비 완료!** 이제 주민센터에 내러 가요." (주의: **제출 완료가 아니다.** 제출은 다녀와서 누른다. 문구에 "냈어요"를 쓰지 않는다)
- **안 챙긴 서류**가 먼저, 큰 카드 하나씩:
  - 서류 이름 (굵게, 22px) / 쉬운 설명 / "📍 {PLACE_LABEL.title}: {issuePlace}"
  - 추가 요청 항목: "📮 추가 요청, {11월 28일}까지" 표시. `alsoRequested`면 "📮 추가 요청에도 있어요"
  - 버튼 `☐ 챙겼어요` (누르면 `☑ 챙겼어요`, 초록 테두리 + 글자 "챙겼어요")
  - 서류 카드 누르기 → 이름과 설명 읽어 주기
- 그 아래 접힌 줄: `✅ 챙긴 서류 {n}개 (펼치기)` → 펼치면 챙긴 것들 (체크 풀 수 있음)
- 맨 아래 **확인할 것** 상자 (`checkTasks`가 있을 때, 피드백 기획 3):
  - 제목 "⚠ 확인할 것 {n}개"
  - 줄마다: "{label}: {display}" + `어디서 확인해요?` → checkGuide 펼침 + `고치기` → `/a/[id]/q?field={key}&from=review`
- 그 아래 **내기 전 점검 남은 것** (`precheckPending`이 있을 때): 줄마다 질문 + 고치는 방법 + `다시 점검하기` → `/a/[id]/precheck`
- 읽어 줄 말: "챙길 서류가 {n}개 남았어요. {안 챙긴 서류 이름들을 차례로}"

### 탭 2: 📍 받으러 갈 곳
- 안 챙긴 서류를 **받는 곳 묶음**(`placeGroup`)별로. 안 챙긴 서류가 있는 묶음이 먼저.
- 묶음 상자: `{icon} {title}` (예: "🏦 은행에서 떼요") / 그 묶음의 서류 이름들 / `tip`
  - `onsite`, `gov24` 묶음 아래: "📍 {구} {동} 주민센터" + `🗺 지도에서 찾기` (새 창 `https://map.naver.com/p/search/{encodeURIComponent(구 + ' ' + 동 + ' 주민센터')}`) + `📞 120에 물어보기` (`tel:120`) + "평일 낮에 가요. 가기 전에 전화로 물어보면 좋아요."
  - `gov24` 묶음: `정부24 열기` (새 창 `https://www.gov.kr`)
  - `bank` 묶음: "가까운 은행 창구에서 서류 이름을 그대로 말하면 돼요."
- 다 챙긴 묶음은 맨 아래에 "✅ 다 챙겼어요"로 작게
- 읽어 줄 말: 묶음별 "은행에서 떼요: 연금 받는 통장 거래 내역" 차례로

### 탭 3: 🗣 주민센터에서 할 말
- 큰 상자 "주민센터 창구에서 이렇게 말하세요" + **할 말** (24px 이상) + `🔊 읽어 주기`
  - 할 말: 처음 열 때 `POST /api/card-script`(03)에 `scriptInput`을 보내 받는다. localStorage `boknyang.script.{appId}`에 답이 바뀐 시각과 같이 저장해서, 답이 안 바뀌었으면 다시 부르지 않는다.
  - 실패하거나 03이 없으면 **틀 문장**: "서울형 기초보장제도 신청하러 왔어요. {applicantType이 family면 '가족 대신 왔어요. '}같이 사는 사람은 {n}명이에요. {checkTasks가 있으면 '정확히 모르는 것이 있어서 같이 확인해 주세요.'}"
  - 추가 요청이 있으면 그 아래 둘째 상자 "추가 서류를 낼 때": "추가 서류 내러 왔어요. {추가 서류 이름들} 가져왔어요."
- **주민센터에서 같이 확인해 달라고 할 것** (checkTasks 이름 목록)
- **낼 곳**: "{구} {동} 주민센터" + 지도 + 120
- `🖨 옮겨 쓰는 카드 출력` 안내: "신청서를 쓸 때 옮겨 쓰는 카드를 보여 주거나 보면서 쓰면 돼요."
- 읽어 줄 말: 할 말

## S7 옮겨 쓰는 카드 `/a/[id]/print` (출력용 한 장)

### 목적
주민센터가 미리 채운 신청서를 받아 주지 않아도, 신청하는 분이나 직원이 **보면서 그대로 옮겨 쓸 수 있게** 공식 신청서 칸 이름(`label`) 그대로, 섹션 순서대로 정리한 한 장.

### 화면 (폰에서도 보이고, 인쇄하면 A4 한 장)
- 폰에서는 AppShell (back `/a/[id]/card`, 지금 할 일 "출력하거나 PDF로 저장해 주세요") + 위에 버튼 두 개:
  - `🖨 출력하기` → `window.print()`
  - 안내 글: "PDF로 저장하려면 출력하기를 누른 뒤 프린터를 PDF로 저장으로 바꾸세요."
- 이름 넣기 (선택): 입력칸 `이름`, `전화번호` + 안내 "적은 이름과 전화번호는 저장하지 않아요. 출력할 때만 들어가요." (화면 상태에만 둔다. localStorage에도 저장하지 않는다)
- 인쇄 영역 `PrintSheet` (검정 글자, 흰 배경):
  1. 제목 "옮겨 쓰는 카드: 사회보장급여 신청서 (서울형 기초보장제도)" + 작성일 (`todayKST`)
  2. 신청인: 이름 `{입력값 또는 빈칸 ________}`, 전화번호 `{입력값 또는 빈칸}`, 주민등록번호 "주민센터에서 직접 써 주세요"
  3. 섹션별 표 (`SECTION_ORDER`, 보이는 질문만): **공식 칸 이름** | **적을 내용**
     - `'unknown'` → 칸은 비우고 "□ 확인 필요: {checkGuide 짧게}"
     - `isApproximate` → "약 30만 원 (확인 필요)" (숫자를 확정 값처럼 쓰지 않는다)
  4. 챙길 서류 체크 목록: 받는 곳 묶음별 "□ 신분증" (챙긴 것은 "☑")
  5. 추가 요청이 있으면: "추가로 챙길 서류 ({11월 28일}까지)" 목록
  6. 주민센터에서 할 말 (짧게)
  7. 맨 아래: "복냥이로 정리한 참고 자료예요. 신청서를 쓸 때 보면서 옮겨 쓰거나 담당자에게 보여 주세요. 받을 수 있는지는 구청 조사 후 정해져요."
- 인쇄 CSS (`@media print`): AppShell, 버튼, 입력칸 숨김. 본문 12~14pt, 표는 테두리, `break-inside: avoid`. **A4 한 장에 들어가게** 여백 12mm, 글자가 넘치면 서류 목록을 두 단으로.
