# 06 시작, 내 신청 현황, 이어서 하기, 주민센터 다녀왔어요, 가족 공유, 보안 점검

> **AI에게:** `docs/00_공통_먼저읽기.md`를 먼저 끝까지 읽는다. 인증은 01의 `requireApp`, 코드 생성은 `newShareCode`, 조건 계산은 `lib/rules/condition.ts`, 날짜는 `lib/format.ts`를 쓴다. 고치지 않는다.

## 이 기능이 하는 일
1. **시작 화면** `/`와 **추가 서류로 바로 시작** `/supplement`
2. **내 신청 현황** `/a/[id]`: 다시 들어온 사람에게 마지막 화면 대신 **남은 일을 먼저** 보여 준다. (피드백 디자인)
3. **이어서 하기** `/resume`: 8자리 번호, **10분에 5번 틀리면 잠금**. (피드백 개발)
4. **주민센터에 다녀오셨어요?** `/a/[id]/visit`와 **주민센터 제출 완료** `/a/[id]/done`: **서류 준비 완료와 제출 완료를 분명히 나눈다.** (피드백 디자인)
5. **가족에게 보내기**: 누를 때만 링크를 만들고, **7일 뒤 만료, 언제든 멈추기**, 가족 화면에는 **금액과 답을 숨긴다.** (피드백 기획 5, 개발)
6. **단계 표시** `StageTracker`, **공유 버튼** `ShareButton` (01의 빈 껍데기를 채움)
7. 마지막에 **보안 점검**과 `README.md`

## API

### 🔒 `GET /api/apps/[id]/progress`
`lib/rules/progress.ts`의 `buildProgress(...)`로 계산:
```ts
interface Progress {
  app: Application;
  programName: string;
  remainingQuestions: number;     // 보이는 필수 질문 중 답 없는 것 ('unknown'은 답으로 봄)
  checkNeeded: number;            // 보이는 답 중 'unknown' 또는 isApproximate
  checklistTotal: number;
  checklistDone: number;
  docsReady: boolean;             // checklistTotal > 0 && 모두 done
  precheckPending: number;        // 해당되는 점검 중 결과가 없거나 no, unknown
  activeSupplement: { id: string; deadline: string | null; deadlineConfirmed: boolean; dday: number | null; itemCount: number } | null; // 아직 안 낸 가장 최근 것
  nextActions: NextAction[];      // 아래 순서로 최대 3개
}
interface NextAction { kind: string; title: string; sub: string; href: string; urgent: boolean; }
```

**남은 일 순서 (위가 먼저)**
| 조건 | title | sub | href | urgent |
|---|---|---|---|---|
| activeSupplement 있음, 기한 확인 전 | 추가 서류 날짜를 확인해 주세요 | 받은 종이와 날짜가 같은지 봐요 | `/a/[id]/extra/{sid}` | O |
| activeSupplement 있음 | 추가로 챙길 서류 {n}개 | {11월 28일 (토)}까지, {7일 남았어요} | `/a/[id]/extra/{sid}` | O |
| status drafting, 남은 질문 있음 | 질문 {n}개 남았어요 | 이어서 대답해요 | `/a/[id]/q` | |
| status drafting, 남은 질문 없음 | 신청서 내용을 확인해 주세요 | 틀린 곳이 없는지 봐요 | `/a/[id]/review` | |
| precheckPending > 0 (drafting 아님) | 내기 전 점검 {n}개 | 다시 달라고 하는 일을 줄여요 | `/a/[id]/precheck` | |
| 체크 안 한 서류 있음 | 챙길 서류 {n}개 남았어요 | {가장 먼저 챙길 서류 이름} 등 | `/a/[id]/card` | |
| checkNeeded > 0 | 확인할 것 {n}개 | 모르는 금액을 확인하면 좋아요 | `/a/[id]/card` | |
| docsReady, 제출 전 | 서류를 다 챙겼어요. 주민센터에 내러 가요 | 다녀오면 결과를 눌러 주세요 | `/a/[id]/visit` | |
| status submitted | 결과를 기다리는 중이에요 | 구청에서 글로 알려 줘요 | `/a/[id]/done` | |
| 체크리스트가 비어 있음 (preparing) | 제출 준비 카드를 열어 주세요 | 챙길 서류를 정리해 드려요 | `/a/[id]/card` | |

### `POST /api/resume` (토큰 없음, 피드백 개발)
1. 요청 `{ code }` → 숫자만 남기고 8자리가 아니면 400 `{ error: 'format', message: '번호 8자리를 눌러 주세요.' }`
2. IP: `x-forwarded-for`의 첫 값 (없으면 `'unknown'`)
3. `resume_attempt`에서 그 IP의 최근 10분 실패 수 ≥ 5 → 429 `{ error: 'locked', message: '번호를 여러 번 틀렸어요. 10분 뒤에 다시 해 주세요.' }`
4. `application.resume_code = code` 찾기
   - 없으면 실패 기록 → 404 `{ error: 'notfound', message: '그 번호가 없어요. 다시 확인해 주세요.', remaining: 남은 시도 수 }`
   - 있으면 성공 기록 → `{ appId, token: app_token, resumeCode }`
   - `expires_at`이 지났으면 404와 같은 메시지 (기간이 지난 신청 건은 열지 않음)

### 🔒 `POST /api/apps/[id]/share`
- 지금 `share_code`가 있고 만료 전이면 그대로, 아니면 `newShareCode()`로 새로 만들고 `share_expires_at = now + 7일`
- 응답 `{ shareUrl: '{origin}/s/{code}', expiresAt }` (origin은 요청 헤더에서)

### 🔒 `DELETE /api/apps/[id]/share`
- `share_code = null`, `share_expires_at = null` → `{ ok: true }` (이전 링크는 바로 안 열림)

### `GET /api/share/[code]` (토큰 없음, 보기 전용)
- 코드가 없거나 만료면 404 `{ error: 'expired', message: '링크가 멈췄거나 기간이 지났어요. 보낸 분께 다시 받아 주세요.' }`
- 응답 `SharedView` — **금액, 답, 동 이름, 이어서 하기 번호, 토큰을 넣지 않는다**:

interface SharedView {

  submittedAt: string | null;

  supplement: { deadline: string | null; dday: number | null; items: { easyName: string; issuePlace: string }[] } | null;
  familyHelpNeeded: boolean;        // 추가 서류나 점검에 "부양의무자", "가족", "자녀"가 들어간 항목이 있으면 true
  expiresAt: string;

## StageTracker `components/status/StageTracker.tsx`
- props는 01 파일 그대로. 00의 10장 표대로.
- 가로 4칸 (좁으면 세로). 칸마다 번호 동그라미 + 이름 + 상태 글:
  - 끝남: ✓ + 굵은 초록 테두리 + "신청서 다 썼어요" / "**서류 준비 완료**" / "**제출 완료 (11월 21일)**"
  - 지금: 굵은 검정 테두리 + "지금"
  - 아직: 얇은 테두리
- supplementing이면 ③ 옆에 "📮 추가 서류 D-7" (글자로)
